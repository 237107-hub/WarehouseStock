- У продуктивному Core: 0 звертань до Console; жодної реалізації файлового
  сховища; лише одна реалізація ITransferRepository, на Dictionary.
- IPricingPolicy та INotifier: по одному методу; ITransferRepository: 3 методи.
- У нових явно написаних рутинах ЦС <= 6, аргументів <= 4, тіло <= 20 рядків;
  докладні синтаксичні вимірювання в metrics.json.

Harness перевіряє справжні складання Core і тестового еталона: закритий життєвий
цикл, спробу обійти AddLine через ICollection, інваріанти конструктора, захист
залишку від недостачі, дублікат ключа, незалежну колекцію GetAll, null-залежності,
границі ставки знижки, незмінність архіву через зовнішнє посилання, точний CSV.
Також відтворено NotSupportedException у Legacy.TransferManager.Archive для
непорожнього документа; виконання зупиняється до запису у файл.

Лістинг harness додано до docs/lab04/smoke-checks.cs.txt для відтворення аудиту;
він не входить до продуктового рішення і не створює додаткових xUnit-тестів.
Фактичні журнали та TRX-результати збережено в evidence. Скріншоти термінала
не створювалися; текстові журнали не називаються скріншотами.

Place спочатку зберігає, потім сповіщає. У разі помилки зовнішнього каналу
збереження не відкочується: транзакції/повторне доставлення не входять до ЛР4.
Сховище не потокобезпечне та повертає ті самі агрегати; це не серіалізація,
не база даних і не глибоке копіювання. Архів стабільний завдяки вимозі
термінального стану, get-only позиціям та ReadOnlyCollection, а не лише readonly.
